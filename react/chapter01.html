Nhập Môn React & JSX

Tự động hóa chính nguyên lý "render lại từ dữ liệu" bạn đã tự tay xây ở Bài 18 chương JavaScript — làm quen với component và cú pháp JSX.

React Cơ bản ⏱ 35 phút

01Giới thiệu

Nhớ lại Bài 18 chương JavaScript: bạn tự viết hàm render() xóa sạch DOM và vẽ lại toàn bộ danh sách mỗi khi dữ liệu thay đổi. Cách này hoạt động tốt cho ứng dụng nhỏ, nhưng với ứng dụng lớn hơn — hàng chục thành phần giao diện, dữ liệu thay đổi liên tục — việc quản lý thủ công như vậy sẽ nhanh chóng trở nên rối rắm.

React là thư viện JavaScript giải quyết đúng vấn đề đó: bạn chỉ cần mô tả giao diện trông như thế nào dựa trên dữ liệu hiện tại, React tự lo phần "render lại" một cách thông minh và hiệu quả (nhờ kỹ thuật Virtual DOM). Toàn bộ giao diện được chia thành các component — những khối UI độc lập, tái sử dụng được, y hệt cách bạn nhìn thấy các card khóa học lặp lại ở trang chủ Full Stack Blueprint.

🎯
Mục tiêu sau bài học

Hiểu component là gì, viết được JSX cơ bản, và dựng được component React đầu tiên hiển thị dữ liệu ra màn hình.

02Kiến thức lý thuyết

2.1. Nhúng React vào HTML (không cần công cụ build)

Dự án React thực tế thường dùng công cụ build (Vite, Create React App). Nhưng để học và thực hành ngay trong một file HTML duy nhất — đúng quy tắc của khóa học này — ta dùng 3 thư viện qua CDN:

nhúng React qua CDN
<script src="https://unpkg.com/react@19/umd/react.development.js"></script>
<script src="https://unpkg.com/react-dom@19/umd/react-dom.development.js"></script>
<script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

<script type="text/babel">
  // code React + JSX viết ở đây
</script>

Babel là công cụ "dịch" JSX (cú pháp trông giống HTML) thành JavaScript thuần mà trình duyệt hiểu được — bắt buộc phải có nếu viết JSX trực tiếp mà không qua bước build.

2.2. JSX là gì?

JSX cho phép viết cấu trúc giao diện trông giống HTML ngay bên trong JavaScript:

JSX cơ bản
const phanTu = <h1>Xin chào React!</h1>;
// thực chất Babel "dịch" dòng trên thành:
// const phanTu = React.createElement("h1", null, "Xin chào React!");

JSX không phải HTML thật — nó là cú pháp đường tắt để gọi React.createElement(), dễ đọc hơn hẳn cách viết thuần.

2.3. Nhúng biểu thức JavaScript vào JSX bằng { }

nhúng biểu thức
const ten = "Full Stack Blueprint";
const phanTu = <h1>Chào mừng đến với {ten}!</h1>;
// bất kỳ biểu thức JS nào cũng dùng được trong { }: biến, phép tính, gọi hàm...

2.4. Ba quy tắc JSX quan trọng cần nhớ

Quy tắcVí dụ
Chỉ một phần tử gốcPhải bọc nhiều phần tử trong một thẻ cha duy nhất (hoặc <>...</>)
Dùng className thay vì class<div className="card">, vì class là từ khóa JavaScript
Mọi thẻ phải tự đóng hoặc có thẻ đóng<img />, <br /> — không được để mở lửng như HTML thường

2.5. Component — hàm trả về JSX

Component React đơn giản nhất chỉ là một hàm (Bài 5, chương JavaScript) trả về JSX, tên luôn viết hoa chữ cái đầu:

component cơ bản
function LoiChao() {
  return <h1>Xin chào từ component!</h1>;
}

03Ví dụ minh họa

Hãy dựng một component hiển thị thông tin một khóa học — đúng dữ liệu bạn từng thao tác bằng tay ở Bài 6, 8 chương JavaScript (object { ten, icon, soBaiHoc }), nhưng lần này để React tự render thay vì gọi document.createElement() thủ công.

04Code mẫu

react-hello.html 
<div id="root"></div>

<script src="https://unpkg.com/react@19/umd/react.development.js"></script>
<script src="https://unpkg.com/react-dom@19/umd/react-dom.development.js"></script>
<script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

<script type="text/babel">
  // Component nhận dữ liệu, trả về JSX mô tả giao diện
  function ThongTinKhoaHoc() {
    const khoaHoc = {
      ten: "HTML & CSS Nền Tảng",
      icon: "🧱",
      soBaiHoc: 11
    };

    return (
      <div className="course-card">
        <span>{khoaHoc.icon}</span>
        <h3>{khoaHoc.ten}</h3>
        <p>{khoaHoc.soBaiHoc} bài học</p>
      </div>
    );
  }

  // "Cắm" component vào phần tử #root có sẵn trong HTML
  const root = ReactDOM.createRoot(document.getElementById("root"));
  root.render(<ThongTinKhoaHoc />);
</script>

05Giải thích code

  • <div id="root"></div> — phần tử HTML "trống" làm điểm neo, nơi React sẽ chèn toàn bộ giao diện nó tạo ra vào.
  • function ThongTinKhoaHoc() { return (...); } — đây là một component, tên viết hoa chữ cái đầu (ThongTinKhoaHoc, không phải thongTinKhoaHoc) để React phân biệt với thẻ HTML thường.
  • <span>{khoaHoc.icon}</span> — dấu ngoặc nhọn nhúng giá trị biến JavaScript trực tiếp vào giữa JSX, y hệt template literal (Bài 1 chương JavaScript) nhưng dùng trong ngữ cảnh JSX.
  • ReactDOM.createRoot(document.getElementById("root")) — vẫn dùng document.getElementById quen thuộc (Bài 8) để tìm điểm neo, sau đó giao quyền quản lý phần tử đó cho React.
  • root.render(<ThongTinKhoaHoc />); — gọi component bằng cú pháp giống thẻ HTML tự đóng, React sẽ chạy hàm ThongTinKhoaHoc, lấy JSX nó trả về, rồi vẽ vào #root.

06Lỗi thường gặp

Nhấp vào từng mục để xem chi tiết lỗi và cách khắc phục:

Viết return <h1>A</h1><p>B</p>; — báo lỗi Adjacent JSX elements must be wrapped in an enclosing tag, vì một component chỉ được trả về đúng một phần tử gốc.

✅ Cách khắc phục: bọc trong một <div>, hoặc dùng <>...</> (Fragment) nếu không muốn thêm thẻ HTML thừa vào DOM.

Viết <div class="card"> (thói quen từ HTML thuần) — React vẫn hiển thị được nhưng cảnh báo trong console, vì class là từ khóa dành riêng trong JavaScript.

✅ Cách khắc phục: luôn dùng className thay cho class trong mọi JSX.

Viết function thongTinKhoaHoc() { } rồi gọi <thongTinKhoaHoc /> — React hiểu nhầm đây là một thẻ HTML thường (như <div>) chứ không phải component, không hiển thị gì.

✅ Cách khắc phục: luôn đặt tên component viết hoa chữ cái đầu (PascalCase) — quy tắc bắt buộc của React, không phải chỉ là gợi ý.

Viết JSX trong thẻ <script> thường (thiếu type="text/babel") — trình duyệt không hiểu cú pháp JSX, báo lỗi cú pháp ngay tại dấu < đầu tiên trong JSX.

✅ Cách khắc phục: mọi thẻ script chứa JSX (khi học không dùng build tool) đều cần type="text/babel" để Babel kịp "dịch" trước khi trình duyệt chạy.

⚠️
Cảnh báo quan trọng

Cách nhúng React qua CDN + Babel standalone (như bài này) chỉ phù hợp để học và thử nghiệm nhanh. Babel standalone dịch JSX ngay trên trình duyệt của người dùng, khá chậm và không tối ưu — dự án React thực tế luôn dùng công cụ build (Vite, Next.js...) để dịch trước, cho ra file JavaScript đã tối ưu sẵn.

07Best Practices

  • Luôn đặt tên component viết hoa chữ cái đầu (PascalCase).
  • Luôn dùng className thay cho class trong JSX.
  • Bọc nhiều phần tử JSX trong một phần tử gốc duy nhất, ưu tiên Fragment (<></>) nếu không cần thêm thẻ HTML thật vào DOM.
  • Giữ mỗi component tập trung vào đúng một phần giao diện, đặt tên rõ ràng theo vai trò hiển thị.
  • Khi làm dự án thật (ngoài phạm vi khóa học này), luôn dùng công cụ build thay vì CDN + Babel standalone.

08Tip & Note

💡
Tip

Trong DevTools, cài extension React Developer Tools (miễn phí) để có thêm tab "Components" hiển thị đúng cây component React đang chạy trên trang — trực quan hơn nhiều so với chỉ nhìn cây DOM thông thường.

📌
Note

Bạn vừa thấy JSX {khoaHoc.icon} hoạt động giống hệt tinh thần template literal ${'{'}...{'}'} đã học ở Bài 1 chương JavaScript — đều là cách nhúng giá trị JavaScript vào giữa nội dung hiển thị. Nắm chắc JavaScript nền tảng chính là lý do JSX sẽ không hề xa lạ với bạn.

11Tổng kết

Qua bài học này, bạn đã nắm được:

  • React tự động hóa việc "render lại từ dữ liệu" mà bạn từng tự viết thủ công ở Bài 18 chương JavaScript.
  • JSX là cú pháp giống HTML nhưng thực chất là JavaScript, cần Babel để "dịch" khi không dùng build tool.
  • Ba quy tắc JSX: một phần tử gốc, className thay class, mọi thẻ đều phải đóng.
  • Component là hàm trả về JSX, tên viết hoa chữ cái đầu, được "cắm" vào trang bằng ReactDOM.createRoot().render().
📖
Đáp án bài tập 3 (gợi ý)

React dùng quy tắc viết hoa để tự động phân biệt giữa thẻ HTML gốc (như <div>, viết thường) và component do người dùng tự định nghĩa (như <HoSoCaNhan />, viết hoa). Nếu không có quy tắc này, React sẽ không biết <thongTin /> nên được hiểu là một thẻ HTML thật (và thử tạo ra thẻ <thongtin> không hợp lệ) hay là một component cần gọi hàm để lấy JSX bên trong.

Với component đầu tiên trong tay, ở Bài 2, bạn sẽ học Props — cách truyền dữ liệu từ component cha xuống component con, biến component tĩnh thành những khối UI thực sự tái sử dụng được với dữ liệu khác nhau.
