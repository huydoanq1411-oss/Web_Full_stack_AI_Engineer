Xử Lý Sự Kiện & Form Trong React

Lắng nghe hành động người dùng đúng "kiểu React", và biến mỗi ô input thành một phần của state — không còn phải tự tay đọc DOM như JavaScript thuần.

React Cơ bản ⏱ 45 phút

01Giới thiệu

Ở Bài 3, state đã cho component "trí nhớ" riêng. Nhưng trí nhớ đó cần được kích hoạt bởi hành động của người dùng — nhấp nút, gõ chữ, chọn checkbox, gửi form. JavaScript thuần dùng addEventListener để lắng nghe những hành động này (Bài 9 chương JavaScript); React có cách tiếp cận riêng, gọn hơn và tích hợp thẳng vào JSX.

Với form, React đề xuất mô hình Controlled Component — nghĩa là giá trị của mỗi ô input luôn được đồng bộ với state, thay vì để trình duyệt tự quản lý. Đây là kỹ năng bạn sẽ dùng trong gần như mọi ứng dụng React thực tế: đăng nhập, tìm kiếm, bình luận, thanh toán...

🎯
Mục tiêu sau bài học

Lắng nghe sự kiện đúng cú pháp React, xây dựng Controlled Component cho input/textarea/checkbox/select, và xử lý submit form an toàn.

02Kiến thức lý thuyết

2.1. Lắng nghe sự kiện trong JSX

cú pháp sự kiện
<button onClick={xuLyClick}>Nhấn vào đây</button>
// KHÔNG viết onClick="xuLyClick()" như HTML thuần — truyền THAM CHIẾU hàm, không gọi hàm

Tên sự kiện React dùng camelCase (onClick, onChange, onSubmit) thay vì chữ thường như HTML (onclick). Quan trọng hơn: giá trị truyền vào là một hàm, không phải chuỗi code như thuộc tính HTML.

2.2. Truyền tham số cho sự kiện

truyền tham số
<button onClick={() => xoaCongViec(id)}>Xóa</button>
// bọc trong arrow function để KHÔNG gọi ngay khi render — chỉ gọi khi thật sự click

2.3. Controlled Component — input đồng bộ với state

controlled input
const [ten, setTen] = useState('');

<input
  value={ten}
  onChange={(e) => setTen(e.target.value)}
/>
// value luôn lấy từ state — onChange cập nhật lại state mỗi khi người dùng gõ

e (event object) chứa e.target — chính là phần tử DOM đang phát sinh sự kiện; e.target.value là nội dung hiện tại của ô input đó. Vòng lặp diễn ra liên tục: gõ chữ → onChange chạy → state đổi → React render lại → value hiển thị đúng ký tự vừa gõ.

2.4. Một handler dùng chung cho nhiều input — thuộc tính name

handler dùng chung
const [form, setForm] = useState({ ten: '', email: '' });

function xuLyThayDoi(e) {
  const { name, value } = e.target;
  setForm(fHienTai => ({ ...fHienTai, [name]: value }));  // [name]: computed property name
}

<input name="ten" value={form.ten} onChange={xuLyThayDoi} />
<input name="email" value={form.email} onChange={xuLyThayDoi} />

Thay vì viết một state và một hàm riêng cho từng ô, gộp cả form thành một object state, dùng thuộc tính name của input để biết cần cập nhật field nào — kỹ thuật computed property name [name]: value (liên hệ Bài 11 chương JavaScript, Object).

2.5. Xử lý submit — luôn gọi preventDefault()

submit form
function xuLyGui(e) {
  e.preventDefault();  // chặn hành vi mặc định: reload lại trang
  console.log('Dữ liệu gửi đi:', form);
}

<form onSubmit={xuLyGui}>
  ...
  <button type="submit">Gửi</button>
</form>

Form HTML mặc định sẽ tải lại trang khi submit — hành vi này có từ thời web chưa có JavaScript. Trong ứng dụng React (SPA — Single Page Application), gần như luôn phải gọi e.preventDefault() đầu tiên trong hàm xử lý submit để ngăn việc đó.

2.6. Checkbox & Select — không dùng value theo cùng cách

Loại inputThuộc tính đọc giá trịEvent lấy giá trị mới
text / textareavaluee.target.value

03Ví dụ minh họa

Xây dựng một form "Thêm công việc" hoàn chỉnh: một ô nhập tiêu đề, một checkbox đánh dấu "Gấp", một select chọn độ ưu tiên, và nút submit — toàn bộ đều là Controlled Component, gộp chung vào một object state duy nhất.

04Code mẫu

form.html 
<div id="root"></div>

<script src="https://unpkg.com/react@19/umd/react.development.js"></script>
<script src="https://unpkg.com/react-dom@19/umd/react-dom.development.js"></script>
<script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

<script type="text/babel">
  const { useState } = React;

  function FormCongViec() {
    const [form, setForm] = useState({ tieuDe: '', gap: false, uuTien: 'thap' });
    const [danhSach, setDanhSach] = useState([]);

    function xuLyThayDoi(e) {
      const { name, value, type, checked } = e.target;
      setForm(fHienTai => ({
        ...fHienTai,
        [name]: type === 'checkbox' ? checked : value // checkbox đọc "checked", còn lại đọc "value"
      }));
    }

    function xuLyGui(e) {
      e.preventDefault();
      if (!form.tieuDe.trim()) return;              // chặn submit rỗng
      setDanhSach(dsHienTai => [...dsHienTai, form]); // thêm bản ghi mới, không sửa mảng gốc
      setForm({ tieuDe: '', gap: false, uuTien: 'thap' }); // reset form sau khi gửi
    }

    return (
      <>
        <form onSubmit={xuLyGui}>
          <input
            name="tieuDe"
            placeholder="Tiêu đề công việc..."
            value={form.tieuDe}
            onChange={xuLyThayDoi}
          />

          <label>
            <input type="checkbox" name="gap" checked={form.gap} onChange={xuLyThayDoi} />
            Gấp
          </label>

          <select name="uuTien" value={form.uuTien} onChange={xuLyThayDoi}>
            <option value="thap">Thấp</option>
            <option value="cao">Cao</option>
          </select>

          <button type="submit">Thêm</button>
        </form>

        <p>Đã thêm: {danhSach.length} công việc</p>
      </>
    );
  }

  const root = ReactDOM.createRoot(document.getElementById('root'));
  root.render(<FormCongViec />);
</script>

05Giải thích code

  • const { name, value, type, checked } = e.target; — destructuring trực tiếp từ phần tử DOM; type cho biết đây là input loại gì, để quyết định đọc checked (checkbox) hay value (còn lại).
  • [name]: type === 'checkbox' ? checked : value — computed property name kết hợp toán tử ba ngôi (Bài 6 chương JavaScript) để một handler xử lý được mọi loại input.
  • if (!form.tieuDe.trim()) return; — validate đơn giản: chặn submit nếu tiêu đề rỗng hoặc chỉ toàn khoảng trắng.
  • setDanhSach(ds => [...ds, form]); — dùng spread (Bài 17 chương JavaScript) để tạo mảng mới thay vì push() làm biến đổi mảng cũ trực tiếp.
  • setForm({ tieuDe: '', gap: false, uuTien: 'thap' }); — reset toàn bộ object state về giá trị ban đầu ngay sau khi thêm thành công.

06Lỗi thường gặp

Nhấp vào từng mục để xem chi tiết lỗi và cách khắc phục:

Không gọi e.preventDefault() trong handler onSubmit — trình duyệt sẽ tải lại toàn bộ trang theo hành vi form HTML mặc định, xóa sạch state hiện tại.

✅ Cách khắc phục: luôn gọi e.preventDefault() làm dòng đầu tiên trong hàm xử lý submit.

Khởi tạo state là useState() (không có giá trị đầu, tức undefined) rồi gán vào value — React cảnh báo input chuyển từ "uncontrolled" (không kiểm soát) sang "controlled" giữa chừng.

✅ Cách khắc phục: luôn khởi tạo state của input bằng giá trị rỗng hợp lệ, ví dụ useState('') cho chuỗi, không để undefined.

Viết onClick={xuLyClick()} (có dấu ngoặc) — hàm chạy ngay khi component render, không đợi người dùng click, y hệt lỗi đã gặp ở Bài 3 với useState.

✅ Cách khắc phục: truyền tham chiếu hàm onClick={xuLyClick}, hoặc bọc arrow function nếu cần truyền tham số.

Viết form.tieuDe = e.target.value; setForm(form); — sửa thẳng vào object cũ rồi mới gọi setter. React so sánh tham chiếu object để quyết định render lại; vì tham chiếu form không đổi, đôi khi React không nhận ra cần cập nhật.

✅ Cách khắc phục: luôn tạo object mới bằng spread — setForm(f => ({ ...f, tieuDe: e.target.value })).

07Best Practices

  • Luôn gọi e.preventDefault() đầu hàm xử lý onSubmit.
  • Gộp các field liên quan vào một object state duy nhất, dùng name + computed property name cho một handler dùng chung.
  • Khởi tạo state input luôn bằng giá trị hợp lệ (chuỗi rỗng, mảng rỗng...), không để undefined.
  • Validate dữ liệu trước khi cập nhật state hoặc gửi đi, ngay trong handler submit.
  • Reset form về trạng thái ban đầu sau khi submit thành công.

08Tip & Note

💡
Tip

Với form phức tạp nhiều field, nhiều validate, thư viện react-hook-form giúp giảm đáng kể code lặp lại — sẽ được học ở Bài 22 (Form nâng cao).

📌
Note

Component "kiểm soát" giá trị input (Controlled) khác với để trình duyệt tự quản lý (Uncontrolled, dùng ref — sẽ học ở Bài 10). React khuyến nghị Controlled cho hầu hết trường hợp vì dễ validate, dễ đồng bộ nhiều nơi.

11Tổng kết

Qua bài học này, bạn đã nắm được:

  • Sự kiện trong JSX dùng camelCase, truyền THAM CHIẾU hàm chứ không gọi ngay.
  • Controlled Component: value/checked lấy từ state, onChange cập nhật lại state.
  • Dùng name + computed property name để một handler quản lý nhiều field.
  • Luôn gọi e.preventDefault() trong onSubmit để tránh tải lại trang.
📖
Đáp án bài tập 3 (gợi ý)

onClick={xuLyClick()} — dấu ngoặc () khiến JavaScript gọi hàm ngay lập tức tại thời điểm JSX được tính toán (tức là mỗi lần component render), rồi lấy kết quả trả về của hàm đó gán cho onClick — không phải chính hàm. Muốn truyền hàm để React tự gọi khi click, phải truyền tham chiếu onClick={xuLyClick} (không ngoặc), hoặc bọc trong arrow function nếu cần truyền tham số.

Bạn đã biết đọc và ghi dữ liệu qua form. Ở Bài 5, học cách hiển thị giao diện có điều kiện — ẩn/hiện phần tử tùy theo state, một kỹ thuật dùng trong hầu hết mọi component thực tế.
