State & useState Hook

Cho component "trí nhớ" của riêng nó — dữ liệu có thể tự thay đổi theo thời gian, và giao diện tự động cập nhật theo mỗi khi nó đổi.

React Cơ bản ⏱ 40 phút

01Giới thiệu

Props (Bài 2) chỉ giải quyết được dữ liệu truyền từ ngoài vào. Nhưng nếu muốn đếm số lần người dùng nhấp vào một nút, hay theo dõi nội dung một ô input đang gõ — dữ liệu đó không đến từ component cha nào cả, nó tự phát sinh và thay đổi ngay bên trong chính component đó. Đây là lúc cần đến state (trạng thái) — "bộ nhớ riêng" của một component.

React cung cấp useState — một Hook (hàm đặc biệt bắt đầu bằng "use") để thêm state vào component. Khi state thay đổi, React tự động render lại component đó — chính xác là điều bạn từng tự viết bằng tay ở hàm render() tại Bài 18 chương JavaScript.

🎯
Mục tiêu sau bài học

Tự dùng useState để tạo state, cập nhật state đúng cách bằng hàm setter, và hiểu vì sao React tự render lại khi state đổi.

02Kiến thức lý thuyết

2.1. Cú pháp useState

cú pháp cơ bản
const [soLuot, setSoLuot] = useState(0);
// soLuot: giá trị hiện tại — setSoLuot: hàm để CẬP NHẬT giá trị đó — 0: giá trị khởi tạo

useState(0) trả về một mảng có 2 phần tử, "bóc" ra bằng destructuring mảng (Bài 7, chương JavaScript): phần tử đầu là giá trị hiện tại, phần tử sau là hàm dùng để đổi giá trị đó.

2.2. Cập nhật state — luôn qua hàm setter

cập nhật state
function DemSoLan() {
  const [soLuot, setSoLuot] = useState(0);

  function xuLyClick() {
    setSoLuot(soLuot + 1); // KHÔNG BAO GIỜ viết soLuot = soLuot + 1
  }

  return <button onClick={xuLyClick}>Đã nhấn: {soLuot}</button>;
}

Tuyệt đối không gán trực tiếp (soLuot = soLuot + 1) — React sẽ không biết giá trị đã đổi và không render lại. Phải luôn gọi hàm setter (setSoLuot(...)) để React nhận biết và tự động cập nhật giao diện.

2.3. State vs Props — khác nhau ở đâu?

PropsState
Nguồn gốcTừ component cha truyền xuốngTự phát sinh bên trong chính component
Ai sửa đượcChỉ component cha (con chỉ đọc)Chính component đó, qua hàm setter
Ví dụten, icon ở Bài 2Số lần click, nội dung input

2.4. Cập nhật state dựa trên giá trị trước đó — dùng hàm callback

Khi giá trị mới phụ thuộc trực tiếp vào giá trị cũ, nên truyền một hàm vào setter thay vì tính toán trực tiếp:

functional update
setSoLuot(soLuotHienTai => soLuotHienTai + 1);
// an toàn hơn khi có nhiều lần cập nhật liên tiếp gần nhau

2.5. Mỗi component có thể có nhiều state độc lập

nhiều state
const [ten, setTen] = useState("");
const [dangSang, setDangSang] = useState(true);
// gọi useState nhiều lần, mỗi lần quản lý một mảnh dữ liệu riêng biệt

03Ví dụ minh họa

Hãy dựng lại chính xác nút Dark Mode ở header trang Full Stack Blueprint theo phong cách React: thay vì classList.toggle() thủ công như Bài 8-9 chương JavaScript, dùng useState để lưu trạng thái "đang sáng hay tối", và để React tự render lại giao diện tương ứng mỗi khi trạng thái đó đổi.

04Code mẫu

state.html 
<div id="root"></div>

<script src="https://unpkg.com/react@19/umd/react.development.js"></script>
<script src="https://unpkg.com/react-dom@19/umd/react-dom.development.js"></script>
<script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>

<script type="text/babel">
  const { useState } = React; // destructuring Hook từ object React

  function NutDoiTheme() {
    const [dangDark, setDangDark] = useState(false);

    function xuLyClick() {
      setDangDark(gtHienTai => !gtHienTai); // functional update — đảo ngược giá trị
    }

    return (
      <div style={{ background: dangDark ? "#0b1f3a" : "#fff", padding: "20px" }}>
        <button onClick={xuLyClick}>
          {dangDark ? "☀️ Chế độ sáng" : "🌙 Chế độ tối"}
        </button>
        <p style={{ color: dangDark ? "white" : "black" }}>
          Hiện đang ở chế độ: {dangDark ? "Tối" : "Sáng"}
        </p>
      </div>
    );
  }

  function BoDemClick() {
    const [soLan, setSoLan] = useState(0);
    return (
      <button onClick={() => setSoLan(soLan + 1)}>
        Đã nhấn {soLan} lần
      </button>
    );
  }

  function App() {
    return (
      <>
        <NutDoiTheme />
        <BoDemClick />
      </>
    );
  }

  const root = ReactDOM.createRoot(document.getElementById("root"));
  root.render(<App />);
</script>

05Giải thích code

  • const { useState } = React; — useState là một hàm nằm trong object React toàn cục (đã nhúng qua CDN), destructuring ra để dùng gọn hơn.
  • const [dangDark, setDangDark] = useState(false); — state khởi tạo là false (mặc định chế độ sáng), dangDark là giá trị đọc, setDangDark là hàm để đổi nó.
  • setDangDark(gtHienTai => !gtHienTai); — dùng functional update để đảo ngược boolean an toàn, không phụ thuộc vào việc đọc trực tiếp dangDark ở thời điểm gọi hàm.
  • style={{ background: ... }} — hai lớp ngoặc nhọn: ngoặc ngoài báo hiệu đây là biểu thức JavaScript (như Bài 1), ngoặc trong là một object JavaScript thường (Bài 6) chứa các thuộc tính CSS viết theo camelCase.
  • onClick={xuLyClick} — cú pháp lắng nghe sự kiện trong React, tương tự tinh thần addEventListener (Bài 9) nhưng viết trực tiếp như một prop đặc biệt trên phần tử JSX.
  • <>...</> trong App — Fragment đã học ở Bài 1, gộp hai component NutDoiTheme và BoDemClick mà không cần thêm <div> bọc ngoài thừa.

06Lỗi thường gặp

Nhấp vào từng mục để xem chi tiết lỗi và cách khắc phục:

Viết soLan = soLan + 1; thay vì setSoLan(soLan + 1); — biến state có thể đổi giá trị trong bộ nhớ, nhưng React không hề biết điều đó xảy ra, nên không render lại, giao diện vẫn hiển thị giá trị cũ.

✅ Cách khắc phục: luôn dùng hàm setter (được trả về từ useState) để cập nhật state, không bao giờ gán trực tiếp.

Viết if (dieuKien) { const [x, setX] = useState(0); } — React báo lỗi Rendered more hooks than during the previous render, vì Hook phải được gọi theo đúng thứ tự giống hệt nhau ở mọi lần render.

✅ Cách khắc phục: luôn gọi mọi Hook (bao gồm useState) ở cấp cao nhất của component, không đặt trong if, vòng lặp, hay hàm lồng bên trong.

Viết onClick={setSoLan(soLan + 1)} (có dấu ngoặc gọi hàm ngay) — hàm này chạy ngay khi render, không phải khi người dùng click, thường gây vòng lặp render vô hạn.

✅ Cách khắc phục: truyền một hàm (không gọi ngay) — hoặc dùng arrow function bọc lại: onClick={() => setSoLan(soLan + 1)}, đúng như code mẫu ở trên.

Viết setSoLan(soLan + 1); console.log(soLan); và mong đợi console.log in ra giá trị mới — thực tế nó vẫn in giá trị cũ, vì cập nhật state là bất đồng bộ (liên hệ Bài 11 chương JavaScript), giá trị mới chỉ có ở lần render tiếp theo.

✅ Cách khắc phục: không mong đợi đọc được giá trị mới ngay sau khi gọi setter trong cùng một hàm; nếu cần logic dựa trên giá trị mới, xử lý ở lần render kế tiếp hoặc dùng useEffect (học ở bài sau).

⚠️
Cảnh báo quan trọng

"Quy tắc của Hooks" (Rules of Hooks) không phải gợi ý — chúng là ràng buộc bắt buộc của React: chỉ gọi Hook ở cấp cao nhất của component, chỉ gọi từ component React (hoặc Hook tùy chỉnh khác), không bao giờ từ hàm thường hay điều kiện. Vi phạm quy tắc này gây lỗi khó lường, đôi khi chỉ xuất hiện sau vài lần tương tác chứ không báo ngay từ đầu.

07Best Practices

  • Luôn cập nhật state qua hàm setter, không bao giờ gán trực tiếp.
  • Gọi mọi Hook ở cấp cao nhất của component, không đặt trong điều kiện/vòng lặp.
  • Dùng functional update (setX(gt => ...)) khi giá trị mới phụ thuộc trực tiếp vào giá trị cũ.
  • Tách mỗi mảnh dữ liệu độc lập thành một useState riêng, thay vì gộp mọi thứ vào một state object phức tạp.
  • Không mong đợi đọc được giá trị state mới ngay sau khi gọi setter trong cùng một hàm.

08Tip & Note

💡
Tip

Trong React Developer Tools, tab Components hiển thị luôn cả state hiện tại của mỗi component (không chỉ props) — nhấp vào một component đang có state để xem và thậm chí chỉnh sửa trực tiếp giá trị đó, quan sát giao diện phản ứng ngay lập tức.

📌
Note

useState là Hook đầu tiên và cơ bản nhất trong một họ các Hook của React (bắt đầu bằng "use"). Ở các bài sau, bạn sẽ gặp thêm useEffect (chạy code khi component tải xong hoặc khi một giá trị đổi) — cả hai đều tuân theo cùng "Quy tắc của Hooks" vừa học.

11Tổng kết

Qua bài học này, bạn đã nắm được:

  • useState cho component "trí nhớ" riêng, trả về cặp [giá trị, hàm setter].
  • Luôn cập nhật state qua hàm setter, không bao giờ gán trực tiếp.
  • Props đến từ ngoài (component cha), State tự phát sinh và quản lý bên trong chính component.
  • Hook phải luôn được gọi ở cấp cao nhất của component, theo đúng thứ tự ở mọi lần render.
📖
Đáp án bài tập 3 (gợi ý)

React không "theo dõi" mọi biến JavaScript thông thường trong component — nó chỉ biết render lại khi được báo hiệu rõ ràng thông qua việc gọi hàm setter do chính useState cung cấp. Gán trực tiếp soLan = soLan + 1; chỉ đổi giá trị trong bộ nhớ ở thời điểm đó, nhưng không kích hoạt được cơ chế render lại của React, nên giao diện tiếp tục hiển thị đúng như lần render gần nhất trước đó.

Với useState, component của bạn giờ đã có thể tự phản ứng với tương tác của người dùng. Ở Bài 4, bạn sẽ học sâu hơn về xử lý sự kiện trong React (event handling) — cách truyền tham số cho sự kiện, và làm việc với form một cách bài bản.
