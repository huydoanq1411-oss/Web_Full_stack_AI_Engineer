12 AI Agent & Tool Use

Bước tiến hóa tiếp theo sau chatbot — LLM không chỉ trả lời mà còn tự hành động: gọi API, tra cứu dữ liệu, thực thi tác vụ.

Chatbot vs AI Agent — khác biệt cốt lõi

Tiêu chíChatbot thông thườngAI Agent
Đầu raChỉ trả lời bằng văn bảnCó thể GỌI HÀM/CÔNG CỤ để thực hiện hành động
Luồng xử lý1 lượt hỏi - 1 lượt đápCó thể lặp nhiều bước: suy nghĩ → hành động → quan sát kết quả → suy nghĩ tiếp
Ví dụTrả lời "Hà Nội là thủ đô Việt Nam"Tự gọi API thời tiết để trả lời "Hà Nội hôm nay bao nhiêu độ?"

Tool Use (Function Calling) hoạt động ra sao?

tool_use_concept.py 
import anthropic

client = anthropic.Anthropic(api_key="your-api-key")

def lay_thoi_tiet(thanh_pho):                # hàm THẬT mà chương trình của bạn định nghĩa
    # trong thực tế sẽ gọi API thời tiết thật, đây là dữ liệu giả lập
    du_lieu = {"Hà Nội": "28°C, nhiều mây", "TP.HCM": "32°C, nắng"}
    return du_lieu.get(thanh_pho, "Không có dữ liệu")

# Khai báo cho LLM biết "công cụ" này tồn tại và cách dùng nó
cong_cu = [{
    "name": "lay_thoi_tiet",
    "description": "Lấy thông tin thời tiết hiện tại của một thành phố",
    "input_schema": {
        "type": "object",
        "properties": {
            "thanh_pho": {"type": "string", "description": "Tên thành phố, VD: Hà Nội"}
        },
        "required": ["thanh_pho"]
    }
}]

response = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=500,
    tools=cong_cu,
    messages=[{"role": "user", "content": "Hà Nội hôm nay thời tiết thế nào?"}]
)

# Nếu LLM quyết định cần gọi công cụ, response sẽ chứa yêu cầu gọi hàm
if response.stop_reason == "tool_use":
    for block in response.content:
        if block.type == "tool_use" and block.name == "lay_thoi_tiet":
            ket_qua = lay_thoi_tiet(block.input["thanh_pho"])   # CHƯƠNG TRÌNH thực thi hàm thật
            print(f"Kết quả từ tool: {ket_qua}")
            # Sau đó gửi kết quả này NGƯỢC LẠI cho LLM để nó tạo câu trả lời cuối cùng bằng ngôn ngữ tự nhiên
Quan trọng
LLM KHÔNG tự thực thi hàm — nó chỉ quyết định "cần gọi hàm nào, với tham số gì" rồi trả về yêu cầu đó. Chương trình của bạn (code Python) mới là nơi THỰC SỰ chạy hàm, sau đó gửi kết quả về lại cho LLM để tạo câu trả lời cuối cùng.
Mẹo
Vòng lặp "suy nghĩ → hành động → quan sát" (thường gọi là ReAct pattern) có thể lặp NHIỀU LẦN trong một câu hỏi phức tạp — VD: agent tự gọi công cụ tìm kiếm, rồi gọi công cụ tính toán trên kết quả tìm được, trước khi trả lời cuối cùng.

Model Context Protocol (MCP) — chuẩn hóa việc kết nối tool

Ví dụ ở trên tự tay khai báo từng "tool" bằng tay — cách này ổn với 1-2 công cụ, nhưng không mở rộng tốt khi bạn cần kết nối agent với hàng chục hệ thống (GitHub, Slack, database, Google Drive...). Từ cuối 2024, Anthropic phát hành MCP (Model Context Protocol) — một chuẩn mở (giống "USB-C cho AI") để chuẩn hóa cách LLM khám phá và gọi công cụ từ các "MCP server" độc lập, không phụ thuộc vào việc bạn dùng LLM nào.

Ghi chú
Đến năm 2026, MCP đã được các hãng AI lớn (OpenAI, Anthropic, Google, Hugging Face...) cùng chuẩn hóa, với hàng chục nghìn MCP server công khai (kết nối GitHub, Slack, PostgreSQL, Google Drive...). Thay vì viết tay từng tool như ví dụ trên, ứng dụng AI hiện đại thường kết nối tới các MCP server có sẵn — hoặc tự viết một MCP server riêng để expose API/dữ liệu nội bộ cho bất kỳ LLM nào dùng lại được, không chỉ riêng ứng dụng của bạn.
